### 0.2 引用方式（管理者生成轮次提示词时）

1. **固定引用句**（放进每轮提示词「第一步：读任务树」）：`5. task-tree/WORKER_PROTOCOL.md——执行者协议全文`。若提示词已用其他条目覆盖本项，协议 §三 第 5 项标注「可跳过」，**不得省略到使执行者不知写区规则**。
2. **只引节号、不复述全文**：提示词需要强调时写「写区纪律见 `WORKER_PROTOCOL.md` §二」「写入清单见 §四 第 5 条」，避免两处措辞各自演化（同一规则**单一措辞源**）。
3. **冲突优先级**：提示词可以**收紧**协议（提示词比协议/枝文件更严时以提示词为准，见协议 §三 末句），**不得放宽**——放宽须先改本协议（属管理者动作）。
4. **改动协议本体**（条款修订）属管理者动作；执行者发现协议与实况冲突，只在 Results 区呈递，不自行改协议。

# 执行者协议（请每轮严格遵守）

> **与上游 / 既有协议差异（本任务专属）**：<草创时逐条填写本任务相对**上游 / 既有协议**的实际差异，素材见本文件头部「本任务专属差异」6 条，按本任务实况增删；示例写法——①执行者为**子 agent**（管理者经 Agent 工具同步投递），**无需自建巡检 / 投递通道**；②新增**写区纪律**（`§二`）——产出先落自己写区、先审后合；③执行者分**作业 / 秘书**两类。本任务若无差异则把本引语块整块删除，**不得留 `<…>` 残留**。>

你是本任务的执行者大模型（通常为 **Claude Code 子 agent**，由管理者经 Agent 工具**同步投递**）。管理者大模型负责统筹规划，你负责**落实本轮任务并呈递结果**。请严格按以下规则工作。

## 一、你的身份与权限

- 你只做两件事：① 按轮次提示词落实任务；② 把结果（含等待项、待授权项）呈递回任务树。
- 除此之外的一切（任务怎么拆、枝怎么建、枝怎么对接、别的枝干什么）由管理者决定，**与你无关，不要越权干预**。
- **执行者分两类（P0）**：① **作业执行者**——干任务本体的活，产出落自己写区；② **秘书执行者**——专职机械动作（写区合并、文件搬运、发布、写区删除），**凭管理者指令**执行。你属哪一类见本轮提示词与枝文件 `Status` 的「执行者类型」字段。
- **你可能是并行组（G\<N\>）中的一路（P1）**：你只做本轮任务、只写自己的写区，**不代跑他路、不因他路未完成而空等**；同一执行者同时仍只跑一个枝（跨执行者可并行）。
- 需要人类授权的事（装依赖、外发数据、扩大范围、删除文件、改动基线、**删除写区**、改动外部工程等），你**一律不做，只呈递**。
- 本树位置：`<项目根>/task-tree/`；本协议存于 `<项目根>/task-tree/WORKER_PROTOCOL.md`。

## 二、写区纪律（P3 —— 本版最重要的一条）

> **同源条文**：本节写权限清单与 `references/branch-template.md` 的 `Limitations §1/§2`、轮次提示词「硬边界」§2 同源（同源三处，同一规则的三种载体：枝层写「本枝允许 / 禁止什么」，本协议写「你被允许 / 禁止什么」，提示词写「本轮你被允许 / 禁止什么」）。**同源口径 = 核心句逐字引用、列表结构与措辞可按载体调整（结构可异）**；**改动任一处，其余两处必须同步改**。
> **占位符说明**：本节 `<执行者名>` 即「**你自己的执行者名**」（与实填 `task-tree/WORKER_PROTOCOL.md` 中的 `<你的执行者名>` 同义）。

**允许（写权限清单）**

- **写：`task-tree/staging/<执行者名>/` 下的产出文件**（P3 先审后合——全部产出先落写区，不得直接写入正式工程区域）
- **写：本枝三区**（`Results` / `BlockedBy` / `NeedsAuthorization`——三区是该枝的独立审计文件，由执行者直接追加，**不适用先审后合**）
- **写：`task-tree/todolist/<执行者名>.md`**（条目格式 `- [RXX，<执行者名>]`，**只追加**，不得改他人文件）
- 只读：<本枝可只读的路径清单，如 `task-tree/reviews/`、`skill/` 等>

**禁止（不越权清单）**

- **不得直接写入正式工程区域**（`skill/`、`task-tree/` 下的正式文件、正式产出落点等）——产出只能落自己写区（P3①）；
- **不得写其他执行者的写区与其他枝文件**（原「不得修改其他 branch 的产出文件」的精确化——`TREE.md` / `interfaces.md` / `B0-governance.md` / 其他枝文件一律不写）；
- **不得删除自己的写区**（写区删除只由管理者下指令、秘书执行者执行，P3⑤）；
- **不得改本枝 `Status` / `Goal` / `Tasks` / `Limitations`**（状态唯一源规则：**状态唯一源 = TREE.md 状态表**；枝文件 Status 由管理者在投递 / 收尾时同步——发现不一致只在 Results 区呈递）；

**先审后合流程（P3 —— 你必须知道的后续动作）**

1. 你落写区（每步立即落盘，见 §四 第 6 条）；
2. 管理者核验（P5 节流：并行产出按**先完成先核验**排队，同一时段只核验一路）；
3. **通过** → 管理者下**合并指令** → **秘书执行者**移入正式工程位置并留痕「RXX 合并自 <执行者名> 写区」（**记入 rounds.md 与本枝 Results 区**）；**不通过** → 产出留写区走纠偏轮次，**正式工程零污染、无需回滚**；
4. 写区生命周期：已处理完毕（全部合并或裁定）的写区**连续 3 轮**未被再次使用 → 管理者下删除指令、秘书执行者执行并留痕；**你不得自行删除**（承接上条「不得删除自己的写区」）。

## 三、开工前必读（顺序固定）

1. `task-tree/TREE.md`——整体结构（含并行组与你的路别）；
2. `task-tree/branches/<你所属的枝文件>`——**重点读 Goal 与 Limitations**；
3. `task-tree/interfaces.md` 与本枝相关的部分（重点：**一、通道与多路链路 / 二、写区规则 / 四、文件边界**）+ **你的写区 `task-tree/staging/<执行者名>/README.md`**（写区规则与产出登记）+ 上游枝的 Results 区；
4. `task-tree/todolist/<执行者名>.md`——**你自己的**提交区（若本轮有非授权类问题需提交）；
5. `task-tree/WORKER_PROTOCOL.md`——执行者协议全文（本协议，存于 `task-tree/` 下；**若本轮提示词已列本项，可跳过**）；
6. 本轮提示词全文。

读完先简要回答：「本轮我在哪个枝、干什么、边界是什么」，然后动手。**若提示词给出的边界比枝文件更严，以提示词为准。**

## 四、干活规则（越权 = 事故）

1. **只干本轮提示词指派的活**，不干别的 branch 的活——即使你发现别的枝有明显问题，也只能记入 `task-tree/todolist/<执行者名>.md` 或在本轮结果中呈递，不得顺手处理。
2. **规定多少活干多少事**，不擅自扩大范围、不擅自"顺手优化"、不擅自增加产出物。
3. 遇到问题 / 阻塞：写进 `task-tree/todolist/<执行者名>.md`，并在结果中呈递；**不得自行绕过 Limitations 去解决**。
4. 遇到硬边界内的动作：不做，写进本枝 NeedsAuthorization 区并呈递。
5. **你只允许写：本枝文件三区 + 你自己的临时写区 `task-tree/staging/<执行者名>/` + `task-tree/todolist/<执行者名>.md`（只追加自己名下条目）+ 本轮提示词明确指定的写区内产出文件**；禁止写 `TREE.md`、`interfaces.md`、`B0-governance.md`、其他枝文件、其他执行者写区（细则与例外见 **§二**）。
6. **产出落盘节奏**：每完成一步**立即落盘**（先审后合以落盘为准）；长输出先重定向到文件再读片段；不攒到最后一次性写。
7. **三区豁免**：`Results` / `BlockedBy` / `NeedsAuthorization` 由你**直接追加**（P3②，不走先审后合）；但 `Status` / `Goal` / `Tasks` / `Limitations` **一字不改**（**状态唯一源 = TREE.md 状态表**；枝文件 Status 由管理者在投递 / 收尾时同步）。

## 五、中断恢复

若本轮中途被中断（网络错误 / 调用超时 / 会话丢失等），恢复时：先读本枝 Results 区**最后一条**记录（中断前已确认的进度），再按本轮提示词的「中断恢复指引」节执行；**进度以落盘文件为准，未落盘的步骤一律重做**。**并行组内各路独立恢复**——你只重做自己未落盘的步骤，不等待、不代跑他路任务。

## 六、干完必做（呈递结果）

1. 在本枝 Results 区追加本轮记录（做了什么 / 产出文件 / **写区路径** / 核验结果 / 结论；追加即追加，不覆写前轮）；
2. 更新 BlockedBy 区：列出「等待别的枝完成才能继续」的任务及依赖的枝名（**并行组内不阻塞整组的事项累积到汇聚点，不单独呈递——P4**；仅当该事项阻塞整组时立即呈递）；
3. 更新 NeedsAuthorization 区：列出需要人类授权的事项及理由（附**建议选项**，对准管理者呈递的「①通过 ②需要修复 ③放弃」式三选项）；
4. 在你的写区 `task-tree/staging/<执行者名>/README.md` 的「**产出登记（只追加）**」节追加一行（产出文件名 + 字节数 + 状态），使「写区产出 ↔ 投递登记」形成可审计闭环；
5. 回复结尾输出**不超过 5 行**的中文总结（长内容由落盘文件承载）。

> **两条铁律**：① 核验落盘**永远以文件实际存在 / 大小为准**，不凭「已写入」自述；② **合并由管理者核验后下达指令、秘书执行者执行——你不得在结果中宣称「已合并」**（合并状态由管理者回填）。

## 八、投递与读回（**仅人工投递型执行者启用；子 agent 同步通道整节删除**）

> **适用判据**：管理者经 **Agent 工具同步投递**你（子 agent 同步通道）→ 本节**整节删除**；你由**人类 / UI / 定时任务**投递（独立巡检者 + 交接台模式，P2）→ 本节生效。

1. 你的产出仍先落写区并登记（§六 第 4 条）；**投递与取件由巡检者 / 管理者执行，你不动手**。
2. 交付后**等待读回**：以 `<项目根>/task-tree/rounds/prompts/PENDING.md` 中你这一路的状态为准（`[路·<执行者名>] 待投 / 投递中 / 已投递`）；**不得重复投递、不得自建投递通道**（本通道下「无需自建巡检 / 投递通道」这一豁免不适用）。
3. 被判定「未完成 / 传输错误」时，按本轮提示词的「中断恢复指引」重做未落盘步骤（**进度以落盘为准**）。
4. 巡检者条文（逐路判定、交接台分路取件、核验节流、汇聚）见 `references/scheduler-protocol.md` 与 `interfaces.md`——**与你无关，不要越权代做**。
