# TREE.md 模板（任务树总览）

> 本文件是三方（人类/管理者/执行者）共享的**唯一事实源入口**。管理者维护，执行者只读。
> 使用方法：管理者草创时复制本模板，把「<…>」占位符全部替换为实际内容后写入项目 `task-tree/TREE.md`。

## 〇、placeholder 填写指引（草创时读；建树后可删除，删除请在 rounds.md R0 记一句）

**A. 哪些节在草创时一次性填（R0 填完即静置）**

| 节 | 填什么 | 何时再动 |
|---|---|---|
| 头部字段 | 项目根绝对路径 / 管理者 / **执行者（多路）** / **临时写区行** / 树版本 `v1` / 最后更新 | 执行者增减、调度变更（记 B0 调度记录） |
| 规范层级 | 与项目内既有规范文件（如 RECURRING_TASK.md 类）的并存关系与冲突裁决顺序 | 新增/废止规范文件时 |
| 一、总目标与验收标准 | 任务目的 + 人类视角的验收清单；**若本项目本身是并行机制试点，验收标准须含「并行组投递/核验/合并走通」条目** | 范围变更时（记 B0 授权台账） |
| 二、Branch 图 | 预埋枝骨架；**每枝尾注「执行者 + 并行组」**，图下加并行组/并行度上限/依赖矩阵指针三行 | 建枝、裁剪枝时（P1） |
| 三、Branch 状态表 | 全部枝（含占位枝）的初始行；**并行组列**无组填「—」 | **每轮更新**（状态 / 当前轮次 / 执行者 / 阻塞原因） |
| 四、对接方案摘要 | 五要点（通道 / 写区 / 交接台 / 核验节流 / 汇聚）+ todolist 分路引用 | 对接方式变更时（同步 `interfaces.md`） |
| **四bis、并行组与依赖矩阵** | 组清单表（组号 / 成员枝 / 并行度 / 说明）+ 依赖矩阵指针；无并行组写「本任务无并行组（全串行）」 | 声明或解散并行组、依赖矩阵变更时（P1/P6） |
| 五、Gate 节点 | Gate 清单（**位置按项目实际标定，不必对应默认三枝**）+ 每个 Gate 的「为什么必须人类决策」 | 到达 Gate 时更新状态列 |
| 六、当前决策清单 | 草创呈递项（树确认 + 并行组分布 + 依赖矩阵 + 首批可投递枝） | **每轮重算**，不是照抄上轮 |
| 七、最近轮次摘要 | R0 建树记录 | **每轮滚动**（保留最近 3 轮） |

**B. 哪些节随轮次更新（活节）**

- **每轮必更**：三、状态表；七、轮次摘要；六、决策清单（无事项写「（暂无）」）。
- **事件驱动**：四bis（并行组声明/解散、依赖矩阵变更——**矩阵本体存 B0-governance.md，本节只放指针**）；五、Gate 状态列。
- **静置节**：头部、规范层级、一、二（仅范围/结构调整时动）。
- **审计只追加**：轮次记录、Gate 决定、决策清单历史项不覆写不删除；错误用新记录更正（§3.5）。

**C. 填写的三条硬规则**

1. **只填事实**：不填期望、设想、未来规划（期望入管理者记忆或另立项；§3.5「树只记事实」）。
2. **占位符必须清零**：`<…>` 全部替换；确无内容的节写「（暂无）」，不留空节、不删节。
3. **并行信息缺一即视为未声明并行**（P1）：并行组**必须**在状态表列（三）、图下声明（二）、四bis 组清单三处**同时出现**；「并行是显式声明，不是默认」。

- 状态枚举（§2.3）：`INACTIVE` → `READY` → `RUNNING` → `BLOCKED` → `DONE`；裁剪枝标 `DEPRECATED`（保文件，不物理删除）。
- **并行组列（P1）**：`G1`/`G2`… 为**显式并行组**；「—」表示默认串行。**并行是显式声明，不是默认。**
- **汇聚完成后**在并行组列写「`~~G1~~ 已汇聚`」（保留痕迹，不回填为「—」），并在四bis 组清单的说明列记汇聚日期与组级结论去向。
- 执行者列：写执行者名（类型见头部「执行者（多路）」行；该处的类型标注为**可选**，执行者名已隐含类型）。

## 四、对接方案摘要（详细见 interfaces.md）

<枝间数据流一句话概括：谁产出什么 → 谁消费什么，格式约定。>

**必含五要点（缺一即对接方案不完整）**：

1. **通道**：<子 agent 同步通道（管理者单条消息内并列多个 Agent 调用，同步返回即判知完成）/ 定时任务独立巡检者通道>；
2. **写区（P3 先审后合）**：产出先落 `task-tree/staging/<执行者名>/`，核验通过后由**秘书执行者**合并并留痕「RXX 合并自 <执行者名> 写区」；树文件三区由执行者直接追加（先审后合的唯一例外）；
3. **交接台**：`task-tree/rounds/prompts/PENDING.md` 按执行者分路（`[路·<执行者名>]`）登记「待投 / 投递中 / 已投递」，各路独立查重与独立锁；子 agent 同步通道下该文件降级为**投递登记与审计台**；
4. **核验节流（P5）**：并行产出按「先完成先核验」排队，管理者**同一时段只核验一路**；上限与顺序声明在 `interfaces.md`；
5. **汇聚（P4）**：组内全部枝 `DONE` 后统一独立核验，以**组级结论一次呈递**（见四bis）。

**todolist 分路**：多执行者工程按路拆文件——`task-tree/todolist/README.md`（规则）、`todolist/<执行者名>.md`（各执行者提交区，只追加自己名下条目，格式 `- [RXX，<执行者名>]`）、`todolist/manager.md`（管理者裁决）、`todolist/human.md`（人类授权）。单执行者工程可沿用单文件 `todolist.md`。

- **依赖矩阵**（每枝：依赖哪些枝的产出 / 被哪些枝依赖 / 共享写哪些文件）存于 `task-tree/branches/B0-governance.md`（P6）——**矩阵是并行分组的唯一依据**。

- **并行度变更**须由管理者更新 `interfaces.md` 并在 B0-governance.md 记明理由。

## 五、Gate 节点（人类决策点，草创时标定）

> 原则：全程 Gate 宜少不宜多（3 个左右）；Gate 之间全自动流转，人类不逐轮介入。
> **注记**：Gate **位置按项目实际标定，不必对应默认三枝**（例如试点项目可把 Gate1 挂在范围枝「试点场景选定」上）；**组级结论在汇聚点呈递（P4）**，故 Gate 可能落在某个并行组汇聚之后。

| Gate | 位置（哪个枝/哪个汇聚点完成后触发） | 为什么必须人类决策 | 状态 |
|---|---|---|---|
| Gate1 | <枝名 / 汇聚点> 完成 | <设计定稿决定整体走向，错了全盘返工> | 待触发 |
| Gate2 | <枝名 / 汇聚点> 完成 | <实现成果是否符合预期，决定是否进入验证> | 待触发 |
| Gate3 | <枝名 / 汇聚点> 完成 | <验收通过决定交付与否> | 待触发 |

- 到达 Gate 时管理者呈递：**质量判断报告 + 固定三选项（①通过 ②需要修复（附具体修复项）③放弃）**。
- 人类的 Gate 决定写入 `B0-governance.md` 的 Gate 决定记录（授权台账），作为后续轮次的硬约束。
