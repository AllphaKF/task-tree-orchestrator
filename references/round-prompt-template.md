# 轮次提示词模板（管理者 → 执行者）

> 管理者每轮按本模板生成提示词，投递给执行者。**不得省略任何一节。**
> 「<…>」为管理者填写；「硬边界」「环境坑」「收尾核验」三节的内容分别来自：该枝 Limitations、该执行者档案（executors/*.md）、管理者本轮定义的核验清单。
> 经验法则（来自多轮实测）：任务拆小、每步落盘、单轮 ≤ 20 分钟；长轮次几乎必然触发传输层中断。

# 第 R<序号> 轮：<本轮主题一句话>

本轮为第 R<序号> 轮。**请全程用中文回复**（仅路径、命令、代码标识符、JSON 键名、已固化的流程名词可保留原文；若平台支持，思考摘要也用中文）。

## 第〇步：会话上下文管理（执行者只接收命令，投递前由人类执行）

- 投递本提示词时**新建对话**（勿在旧对话中追加）——执行者上下文只含本轮命令，专注本轮，省 token；
- 旧对话及其历史**完整留存**，供管理者复查；新对话改名「落地环节-<N>」（N=轮次序号），与轮次编号对应，作为复查索引；
- 执行者开工后一切事实以树文件与本轮提示词为准，**不得引用任何对话历史中的旧信息**（防旧基线幻觉）。

## 第一步：读任务树（动手前必做，顺序固定）

1. 读 `<项目绝对路径>/task-tree/TREE.md`——了解整体结构与你本轮的工作位置；
2. 读 `<项目绝对路径>/task-tree/branches/<本枝文件>.md`——**重点读 Goal 与 Limitations**，这是你本轮的全部权限边界；
3. 读 `<项目绝对路径>/task-tree/interfaces.md` 中与本枝相关的对接方案，以及上游枝 `<列出上游枝文件路径>` 的 Results 区；
4. 读 `<项目绝对路径>/task-tree/todolist.md` 的「执行者提交区」，看是否有与你本轮相关的事项；
5. 读 `<项目绝对路径>/task-tree/WORKER_PROTOCOL.md`——执行者协议全文。

读完先简要回答：**「本轮我在哪个枝、干什么、边界是什么」**，然后动手。

## 中断恢复指引（若本轮中途被中断，恢复时按此执行）

1. 先读 `<本枝文件路径>` 的 **Results** 区**最后一条**记录——那是中断前已确认完成的进度；
2. 再读 `task-tree/todolist.md` 的「执行者提交区」看中断前有无未决事项；
3. **进度以落盘文件为准**：已写入磁盘的产出才视为已完成，未落盘的步骤一律重做（不要凭记忆认为"做过了"）；
4. 重跑本提示词「收尾核验」清单，确认当前实际状态后，从**第一个未完成的任务**继续，不重复已完成的；
5. 继续遵守本提示词的「硬边界」与「环境坑」两节。

## 呈递格式（干完按此执行）

1. 在 `<本枝文件路径>` 的 **Results** 区追加本轮记录（做了什么/产出文件/核验结果/结论）；
2. 更新 **BlockedBy** 区：列出「等待别的枝完成才能继续」的任务及依赖的枝名；
3. 更新 **NeedsAuthorization** 区：列出需要人类授权的事项及理由；
4. 有问题但非授权类：写入 `todolist.md` 的「执行者提交区」；
5. 回复结尾输出**不超过 5 行的中文总结**，不要重复输出同一段内容。

## 管理者补充规则（不随提示词下发，管理者自查用）

- **确定性生成**：提示词必须**从本模板 + 树文件 + 执行者档案严格生成**——「硬边界」逐字转写自该枝 Limitations 的禁止清单，「环境坑」逐字转写自执行者档案；**不得自由发挥、不得凭印象改写**（生成 ≠ 手写：模板是骨架，内容是树里已固化的约束的转写）。
- **投递前**：提示词存盘 `task-tree/rounds/prompts/round-R<序号>-prompt.md`；确认上一轮已结束（判定方法见执行者档案）；确认执行者环境权限模式符合人类要求（跳过模式而非自动模式）；把本枝状态改为 `RUNNING` 并记入 rounds.md。
- **投递后验证**：确认提示词首句与末段完整送达、新轮次已启动、会话名/编号正确（判据见执行者档案）。
- **纠偏轮次的写法**：若上一轮产出有误，本轮任务必须先显式指出「哪些产出要纠正/删除、为什么」，再布置新任务；不得让执行者自行猜测。
- **纠偏内容若与执行者的理解冲突**：给出管理者的实测证据（文件路径+行号+实测值），而不是只给结论。
- **非 Gate 轮次不打扰人类**：本轮发现的小问题、执行者提交的 todolist 事项，累积处理；只有到达 Gate 节点（见 TREE.md）才向人类呈递质量判断报告 + 三选项。
