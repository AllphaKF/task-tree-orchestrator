# 轮次提示词模板（管理者 → 执行者）

> 管理者每轮按本模板生成提示词，投递给执行者。**不得省略任何一节。**
>
> **通道分支（P2 —— 先读这一句）**：本模板含**两种模式**——**模式 A：人工投递通道版**（人类新建对话 / UI / 多窗口独立对话 / 定时任务）与**模式 B：子 agent 同步通道版**（管理者在单条消息内并列多个 Agent 调用、同步返回）。
> 生成提示词时**先按 `references/scheduler-protocol.md`「第 0 步 0.1 模式选择规则」选定模式**，然后**只保留该模式的段落、删除另一模式的段落**（模板并置两版的目的：通道更换时**无需回滚模板**，与 `references/scheduler-protocol.md` 头部通道分支、`references/worker-protocol.md` §八 同法）。
>
> 「<…>」为管理者填写。三节内容的来源（**只准转写，不准自由发挥**）：「硬边界」← 该枝 `Limitations`；「环境坑」← 该执行者档案（`executors/<执行者名>.md`）；「收尾核验」← 管理者本轮定义的核验清单 + 本模板固定必含项（见「零」）。
>
> **写区（P3）**：本模板的「写区落盘要求」节要求执行者把**本轮全部产出**先落自己写区 `task-tree/staging/<执行者名>/`——**该路径必须由管理者在提示词中写死**（不得留空、不得由执行者自拟）。
>
> 经验法则（来自多轮实测）：任务拆小、每步落盘、单轮 ≤ 20 分钟；长轮次几乎必然触发传输层中断。
>
> **本「模板说明」与「零、管理者使用指引」两节不随提示词下发**——生成提示词时整段删除，只保留下方分隔线之后的正文。

## 零、管理者使用指引（**不随提示词下发**，管理者生成 / 投递 / 回填时自查用；生成提示词时整段删除）

> 本节是模板的核心价值：说明 placeholder 怎么填（0.2）、两种模式下哪些段落保留（0.3）、投递前后各查什么（0.4 / 0.5），以及生成时的确定性规则（0.1）。

### 0.1 确定性生成规则（硬规则，违反即模板失效）

1. **严格生成**：提示词必须**从本模板 + 树文件 + 执行者档案严格生成**——「硬边界」**逐字转写**自该枝 `Limitations §2` 的禁止清单（连标点与 `**` 强调符一并保留，**不得改写、不得归纳、不得增删**）；「环境坑」**核心句逐字转写**自执行者档案的「已知环境坑」节且**来源标注必含**（条目可压缩、可合并同类项，**但每条的实测来源标注不得省略**）；「读树指令」「收尾核验」「呈递格式」按本模板固定骨架填写。
2. **生成 ≠ 手写**：模板是骨架，内容是树里已固化的约束的**转写**。**不得凭印象改写、不得自由发挥**、不得因「本轮简单」而省略任何一节（尤其「写区落盘要求」「硬边界」「收尾核验」三节）。
3. **数值与路径写死**：写区路径、产出文件路径、基线 md5 / mtime、字节数、只读豁免路径一律**写具体值**（路径写错是常见的空转原因）。
4. **单一措辞源**：写区纪律、三区豁免、通道判定等已固化的规则**只引节号、不复述全文**（如「写区纪律见 `WORKER_PROTOCOL.md` §二」），避免两处措辞各自演化。提示词可以**收紧**协议 / 枝文件，**不得放宽**（放宽须先改协议，属管理者动作）。
5. **纠偏轮次**：若上一轮产出有误，本轮「本轮任务」节**必须先显式指出「哪些产出要纠正 / 删除、为什么」**，再布置新任务；不得让执行者自行猜测。纠正内容若与执行者的理解冲突，须给出**管理者实测证据（文件路径 + 行号 + 实测值）**，而不是只给结论。
6. **非 Gate 轮次不打扰人类**：本轮发现的小问题、执行者提交的 todolist 事项，累积处理；只有到达 Gate 节点（见 `TREE.md`）才向人类呈递质量判断报告 + 固定三选项。
7. **以目的为导向**：只为流程完整而堆砌的轮次应被质疑并替换（`SKILL.md` 铁律 5）。

### 0.3 通道开关表（决定第〇步 / 投递检查项保留哪一版）

| 开关 | 取值 | 处置 |
|---|---|---|
| 通道 | **模式 A：人工投递**（人类新建对话 / UI / 多窗口独立对话 / 定时任务；执行者有自身会话概念） | 第〇步保留 **(甲) 人工投递版**，删除 (乙)；投递前 / 后检查项用 0.4-A / 0.5-A；巡检条文见 `references/scheduler-protocol.md` **模式 A（独立巡检者 + 交接台）** |
| 通道 | **模式 B：子 agent 同步**（管理者单条消息内并列 Agent 调用、同步返回、无独立会话） | 第〇步保留 **(乙) 子 agent 同步版**，删除 (甲)；投递前 / 后检查项用 0.4-B / 0.5-B；**独立巡检者环节豁免**、管理者兼判定 |
| 路数 | **并行组多路** | 「执行者身份」节声明并行同伴；同组各路**在同一消息内并列投递**（模式 B）或**同批投递、各路独立**（模式 A）；核验按 P5 节流 |
| 路数 | **单路（默认，串行）** | 写「本轮为单路（无并行同伴）」；不引用并行组条款（**并行是显式声明，不是默认**——P1） |
| 执行者类型 | **秘书执行者** | 「本轮任务」按机械动作写（移动 / 追加 / 留痕），**不判断内容质量**；「写区落盘要求」节改写为**写入豁免**（见 0.2 该行） |

- **混合工程逐路选择**（`references/scheduler-protocol.md` 0.1）：同一棵树里部分路为人工投递、部分路为子 agent 时，**按路选模式**，同一轮可 A/B 并存；**不得因「另一路用的是 B」而给人工投递路套用 B 的写法**（反之亦然）。
- **模式变更**（执行者通道更换）属管理者动作：在 `interfaces.md` 记明变更原因与时间，**本模板条文不改**（双模式并置的目的）。

### 0.4 投递前检查项

**共用（两模式）**

- [ ] 本轮任务已**拆小**（单轮 ≤ 20 分钟）、每步立即落盘、路径全部写死；
- [ ] 写区路径已在「写区落盘要求」节**写死**（含产出文件名）；`staging/<执行者名>/README.md` 已存在（缺则先建）；
- [ ] 「硬边界」§1 为 `Limitations §2` **逐字粘贴**（比对一致）；「环境坑」自档案转写，**核心句逐字、来源标注必含**（条目可压缩，来源标注不得省略）；
- [ ] 「收尾核验」含本模板固定必含项（产出存在且非空 / 既有文件未改动 / 未越区写入），并给出本轮基线 md5 或 mtime；
- [ ] 「只读豁免路径」已逐条列明，或明写「本轮不需要访问本任务实例之外的任何路径」；
- [ ] 提示词已存盘 `task-tree/rounds/prompts/round-R<序号>-<执行者名>-prompt.md`（**取执行者名、一路一份**），并已在 `rounds/prompts/PENDING.md` 按路登记为 `**投递中**`（`[路·<执行者名>]` 分节）；
- [ ] 该枝 `Status` 已改 `RUNNING`、当前轮次已填，并记入 `rounds.md`；
- [ ] **该执行者的上一轮已结束**（判定方法：模式 A 见 `references/scheduler-protocol.md` 2.1(甲)；模式 B 见 2.2(乙)）——**限定到执行者维度**：不同执行者可并行，同一执行者绝不得续投；
- [ ] **两个写入者写同一批文件**是绝对禁止的：并行组内多路须各自写区物理隔离（`staging/<执行者名>/`）。

**模式 A 专属**

- [ ] 投递动作由**人类 / UI / 定时任务**完成（管理者不代投）；巡检者与交接台条文按 `references/scheduler-protocol.md` 模式 A（取件投递前先查重、置「投递中」锁）；
- [ ] 权限模式检查：执行者环境权限模式符合人类要求（如「跳过模式」而非「自动模式」），不符先纠正再投递（模式 B 下子 agent 无独立权限模式，**此项豁免**）；
- [ ] 人类在场保护与「新建对话」要求已写进第〇步 (甲)（会话命名「落地环节-<N>」、旧对话完整留存）。

**模式 B 专属**

- [ ] **同组各路在同一消息内并列投递**（调用数 = 并行度，并行度 ≤ `interfaces.md` 声明的上限）；
- [ ] 无对话概念——提示词第〇步用 (乙) 版（独立 Agent 调用 / 无历史上下文 / 管理者运行期间不追加消息）；
- [ ] 每个 Agent 调用不带 `model` 参数（继承主模型），`subagent_type` 按档案。

### 0.5 投递后检查项

**共用（两模式）**

- [ ] 回填 `PENDING.md` 该路状态（`投递中` → `已投递` / `已返回`）与投递时间；**返回时回填返回时间 / 产物路径 / 核验结论**（三字段齐全）；
- [ ] 核验交付（`SKILL.md` §3.4：不信自述、独立验证；**核验落盘以文件实际存在 / 大小为准**）；
- [ ] **P5 核验节流**：并行产出按「**先完成先核验**」排队，管理者**同一时段只核验一路**（核验本身不并行）；上限与顺序见 `interfaces.md`；
- [ ] 核验通过 → 下达**合并指令** → **秘书执行者**移入正式工程位置并留痕「RXX 合并自 <执行者名> 写区」（记 `rounds.md` 与本枝 Results）；**不通过** → 产出留写区走纠偏轮次（正式工程零污染、不生成回滚动作）；
- [ ] 回写：`rounds.md`（一轮可含多路）、各枝状态、`todolist/<执行者名>.md` 并入决策清单；**P4**：组内全部枝 `DONE` 后，组级结论**一次呈递**（单枝待裁事项累积到汇聚点，不单独呈递——除非阻塞整组）。

**模式 A 专属**

- [ ] 确认提示词完整送达（首末句完整、新轮次已启动、会话名 / 编号正确）；验证方法按执行者档案；
- [ ] 巡检者逐路判定（底层事件配对 + UI 辅证、**勿信 mtime**），判完**逐路呈报**管理者；巡检者**不做核验、不生成轮次、不写树**；
- [ ] 异常（断联 / 锁超时 / 通知失败）→ 不自行处置，按异常分支上报；无新事件则本轮休眠。

**模式 B 专属**

- [ ] **同步返回即判知完成**；完成判据 = 返回文本含「落盘产出 + ≤5 行中文总结」且产出文件在写区**实际存在且非空**；
- [ ] **未完成判据** = 调用**报错 / 超时** → 按该轮提示词「中断恢复指引」重投（进度以落盘为准，未落盘步骤重做）；模式 B **不适用**模式 A 的「未完成 / 传输错误」分支（其表现为调用报错）；
- [ ] 多路各自独立返回，**先返回先进入核验排队**，不等待未返回的路。

- [ ] 轮次编号、执行者身份（含执行者类型 / 并行组定位）、通道模式三者已填且与树文件一致；
- [ ] 「模板说明」「零、管理者使用指引」两节**已整段删除**；**placeholder / 定界符全文检索归零**——生成后 `grep -n '<'` 与 `grep -n 'RXX'` 双查，确认 `<…>`、`<执行者名>`、`<序号>`、`<项目名>` 等**半实填形态**与 `<秘书执行者轮次——…>` 类**说明块定界符**均已实例化或删除；
- [ ] **基线数值为具体值**：收尾核验节给出的基线 md5 / mtime / 字节数**必须是实测具体值**（非「须早于本轮开始时间」类关系式表述）；
- [ ] 第〇步**只保留一个模式**（另一模式整段删除）；
- [ ] 「写区落盘要求」节存在且**写死写区路径 + 产出文件名**；
- [ ] 「硬边界」四段齐全（枝清单逐字 / 写区边界核心句逐字 / 外部工程边界含只读豁免 / 兜底句）；
- [ ] 「环境坑」自档案转写，**核心句逐字、每条来源标注必含**（压缩条目亦可，来源标注不得省略）；
- [ ] 「收尾核验」含固定必含项与基线值；「呈递格式」含三区豁免明文 + `todolist/<执行者名>.md`；
- [ ] 「中断恢复指引」含「并行组内各路独立恢复、不等待、不代跑他路」（并行组轮次必含）。

- [ ] 第〇步 (甲) 已含「**新建对话**」与「会话改名『落地环节-<N>』、旧对话完整留存」要求（人类在场保护条款的落点）；

- [ ] 提示词中**不含**模式 B 专属表述（「Agent 调用」「并列投递」「子 agent 无独立会话」等）。

- [ ] 第〇步 (乙) 已含四项：独立 Agent 调用 / 无历史上下文 / 管理者运行期间不追加消息 / 事实来源只有树文件与本轮提示词；
- [ ] 投递前 / 后按 0.4-B / 0.5-B 处理（免权限模式检查、免人类在场保护）；
- [ ] 提示词中**不含**模式 A 专属表述（「新建对话」「落地环节-<N>」「UI 投递」「交接台取件」等）。
