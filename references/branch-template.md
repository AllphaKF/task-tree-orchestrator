# Branch 文件模板（`task-tree/branches/<枝名>.md`）

> **管理者草创时复制本模板创建每个枝的文件**（包括预埋占位枝）。**`# <枝名>（<枝号>）` 一行以下才是枝文件正文**——上方「模板说明」与「零、placeholder 填写指引」两节属模板自带的使用说明，复制建枝时**整段删除**。
>
> **Limitations 必须在草创阶段写满写细，即使该枝尚未激活。**
>
> **状态唯一源规则（P）**：**状态唯一源 = TREE.md 状态表**；枝文件 Status 由管理者在投递 / 收尾时同步。`Status`、`Goal`、`Tasks`、`Limitations` 四区**只有管理者可改**；执行者只被允许追加 `Results` / `BlockedBy` / `NeedsAuthorization` 三区。**三区是该枝的独立审计文件，不构成并行写冲突，且是呈递通道本身**——三区**不适用「先审后合」**，由执行者直接写入。执行者发现状态与实况不一致时，**不得自行改 Status**，只在 Results 区呈递，由管理者同步。
>
> **写区规则（P3）**：执行者的全部产出**先落自己的临时写区** `task-tree/staging/<执行者名>/`，**不得直接写入正式工程区域**；管理者核验通过后下达合并指令，由**秘书执行者**移入正式工程位置并留痕「RXX 合并自 <执行者名> 写区」。
>
> **执行者分两类（P0）**：①**作业执行者**——干任务本体的活，产出落自己写区；②**秘书执行者**——专职机械动作（写区合并、文件搬运、发布、写区删除），由人类分配或管理者在调度权内指派；**管理者只核验、只下指令，不亲手干活**。
>
> **同源条文口径（P）**：**本模板 `Limitations §1/§2` 的核心句清单是「写权限 / 禁止项」的正源**。其他载体（`references/worker-protocol.md` 的「写区纪律」节、`references/round-prompt-template.md` 的硬边界节等）**逐字引用核心句**即可——统一口径：**核心句逐字、列表结构可异**。即：列表项前缀、并句拆分、尾部 `（P3①）` 类括注允许不同；每条权限 / 禁止项的**主干句不得改写、不得合并省略**。
>
> **通道注记（子 agent 同步通道，现行）**：执行者为**子 agent 同步通道**——管理者在单条消息内并列投递多个 Agent 调用、同步返回即判知完成，**独立巡检者环节豁免**，管理者兼判定。若未来回到 UI / 定时任务通道，巡检者与交接台条文按 `references/scheduler-protocol.md` 默认模式执行（本模板字段不变）。

## 零、placeholder 填写指引（草创时先读；复制建枝时**整段删除**）

> 本节是模板的核心价值：说明每个 placeholder 在**草创时**怎么填、由谁填、什么时候补。填写顺序建议自下而上——**先写满 Limitations，再定 Goal / Tasks，最后回填 Status**。

### 0.1 填写责任与时机

| 区段 | 谁填 | 何时填 | 备注 |
|---|---|---|---|
| `# <枝名>（<枝号>）` | 管理者 | 草创 | 枝名须与文件名、TREE.md 状态表三处一致 |
| `## Status` 状态词 | 管理者 | 草创填 `INACTIVE` | **状态唯一源 = TREE.md 状态表**；本处由管理者投递 / 收尾时同步，执行者不写 |
| `## Status` 当前轮次 / 执行者 | 管理者 | **投递时**更新 | READY 之前留 `—` |
| `## Status` 执行者类型 | 管理者 | 可选 | **可选字段**——执行者名已隐含类型、TREE.md 状态表已记执行者；填则与档案一致 |
| `## Status` 并行组 | 管理者 | 草创先填 `—`；声明并行组后回填 | 与 TREE.md 状态表第 6 列、B0-governance 并行组标定三处一致 |
| `## Goal` / `## Tasks` | 管理者 | 草创写目标骨架，逐轮追加任务 | 不活跃的占位枝也必须有 Goal 与 Tasks 位（可写「待激活后细化」） |
| `## Limitations` 四小节 | 管理者 | **草创必须写满写细** | 预埋结构的关键，见 0.3 必含项清单；本模板是核心句正源 |
| `## Results` 三区 | **执行者** | 每轮结束时追加 | 只追加不覆写；标题式与列表项式**两式皆可**；管理者巡检后确认 |
| `## 授权台账` | 管理者 | 仅 `B0-governance.md` 保留 | **其余枝草创时整节删除** |

### 0.2 逐字段填写要点

- **`<枝名>（<枝号>）`**：命名 `B<N>-<动词>-<主题>`（如 `B2-audit-spec`、`B3-impl-ui`），枝号在树内唯一；`B0` 为治理枝、`BV` 为验证枝、`BD` 为交付枝（沿用骨架约定）。
- **`Status` 状态词**：只能取 `INACTIVE | READY | RUNNING | BLOCKED | DONE | DEPRECATED` 六个值之一；可加一句注记说明现状（如 `` `BLOCKED`（等 Gate1 裁定） ``）。**只有 `READY` 才允许生成轮次提示词投递**；执行者同时只允许一个枝处于 `RUNNING`（同一执行者维度，跨执行者可并行）。**状态唯一源 = TREE.md 状态表**；本处由管理者在投递 / 收尾时同步，执行者发现不一致只在 Results 区呈递。
- **`- 并行组`**：填 `**G1**` / `**G2**` / `—`；**`—` 表示默认串行**。并行是**显式声明、不是默认**（P1）——同一并行组内可并行投递，**组间按依赖顺序串行**；同一执行者同时仍然只跑一个枝。并行组须先由管理者在 `B0-governance.md` 依据**依赖矩阵**标定，再回填本字段（矩阵未列明的依赖视为不存在，若并行中发现隐性依赖立即停组呈报）。
- **`- 执行者`**：执行者名与档案路径一致（档案 `executors/<执行者名>.md`，如 `sub-spec`）。
- **`- 执行者类型`（可选）**：作业执行者（默认）/ 秘书执行者。**标注为可选的理由**：执行者名已隐含类型、TREE.md 状态表已记执行者；**实填层不填不影响枝文件成立**，填则须与档案一致。凡其他载体（提示词、SKILL 条文）引用本字段处，同样按**可选**处理。
- **`Goal`**：1–3 句话的可验收目标 + 验收标准（标准要能被独立核验，不写「做好」这类不可判定的词）；若本枝本身是并行机制试点，验收标准须含「并行组投递 / 核验 / 合并走通」条目。
- **`Tasks`**：按「单轮 ≤ 20 分钟」拆成原子任务；任务行尾**可选**加投递注记，便于管理层核对并行度，如 `（并行组 G1，R2 同投）`。
- **`Limitations §3 依赖`**：写明依赖哪些枝的**哪些产出**（位置 + 格式）；并行组内多路共读的资源单列一行「共享只读资源（多路同读、无人写）」——**只读共享不构成写冲突**，这正是可并行的判据。
- **`Limitations §4 产出`**：分两段写——**先落**（`staging/<执行者名>/<产出文件名>`）与**合并目标**（正式位置，注明「待管理者核验通过、秘书执行者执行」）。**不得把正式位置写成执行者的直接落盘点**。
- **`Results`**：执行者按固定块追加；**标题式（`### R<序号>（<执行者名>，<日期>）` + 字段）与列表项式（`- 【R<序号>，执行者，日期】…`）两式皆可**，同枝内保持一致、字段信息不得缺；`核验结果` 必须区分「执行者自报」与「管理者独立核验」；`合并状态` 由管理者在下达合并指令后更新，**执行者不得自报「已合并」**。
- **`BlockedBy`**：只写「等待 `<枝名>` 完成后才能继续 `<任务>`」；**并行组内不阻塞整组的事项累积到汇聚点，不单独呈递**（P4）。
- **`NeedsAuthorization`**：只写需人类授权的事 + 理由 + **建议选项**（对准 §3.6 的「三选项」呈递格式）；人类批复后由管理者移入 `B0-governance.md` 授权台账，并把本区条目划掉。
- **`授权台账`**：**仅 `B0-governance.md` 保留本节**（它是治理枝的专属存档）。**其余枝草创时删除整节**——每枝都带一份台账属结构性冗余，多枝并行下更易误写。

### 0.3 草创自查清单（新枝文件必须全过，缺一即不得标 `READY`）

- [ ] `Limitations §1` 已写明**三条写权限**：本枝三区、`staging/<执行者名>/`、`todolist/<执行者名>.md`；
- [ ] `Limitations §2` 已写明三条禁止项：不得写正式工程区域、不得写他人写区、不得删除自己的写区；

- [ ] 本枝**已删除**「授权台账」节（B0-governance 除外）；
- [ ] 本枝**已删除**本指引节（0.1–0.3）；
- [ ] TREE.md 状态表已同步登记本枝（含「并行组」列），`interfaces.md` 对接表已同步（若涉及枝间数据流）。
